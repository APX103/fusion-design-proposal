逆向x-IMU3（Madgwick）

短板：固定增益，无协方差/速度；无法自适应噪声；无温漂处理。

逆向ATOM-IMU（恒温 + 标定）

擅长：从源头消掉温漂；标定流程最严谨。

短板：功耗/预热/体积；必须有加热硬件；无绝对航向。

融合结论：三者的优点不冲突——ATOM 解决“输入误差”（温度/标定）， x-IMU3 解决“观测鲁棒性”（门控滞回/恢复/时基），自研 EKF 解决“最优融合与可观测性”。 推荐做成 公共底座 + 三档滤波器：标定/温控一次做好； 80 MHz 用 Madgwick，170 MHz 用 6 状态误差状态 EKF，300 MHz 以上用 9/12 状态 ES-EKF， 同一套门控与时间戳机制贯穿三档。

共同点（可以互相印证的部分）

  • 预测—修正结构：陀螺积分做预测，加计/磁计做修正，零偏单独处理。
  • 都需要“静止窗口”：自研用于零偏/对准，x-IMU3 用于初始化，ATOM 用于温度稳定与标定。
  • 都要处理磁干扰与线加速度：自研用卡方门控，x-IMU3 用抑制计数器，ATOM 用温态标定降低系统误差。
  • 都依赖归一化：四元数/重力/磁场矢量归一化是数值稳定的前提。

本质差异（决定选型的三点）

  • 误差怎么被“看见”：EKF 用协方差与创新（可自适应）；Madgwick 用固定增益（简单但不自适应）；ATOM 也是 Madgwick，但只做六轴、并把误差源（温度）拿掉。
  • 零偏由谁负责：自研=滤波器外的静止估计（会被匀速旋转污染）；x-IMU3=引擎状态（与静止解耦）；ATOM=生产/使用前标定（最准但一次性）。
  • 算力换什么：EKF 用矩阵运算换可观测性与不确定性；Madgwick 用极低算力换鲁棒；ATOM 用硬件功耗换热稳定性。

4板级证据：器件与布局也在为误差预算服务

两家的板子走了相反路线。x-IMU3 是“传感器种类齐全 + 磁绝对航向”， ATOM 是“双 IMU + 恒温、没有磁和高 g”。器件型号由电气规格、封装与固件交叉推断（CAD 无丝印）。

x-IMU3：三颗传感器分立

  • 主 IMU：±24g / ±2000dps / 0.014°/s/√Hz → Bosch BMI088（高置信）
  • 磁力计：±1300µT(XY) / ±2500µT(Z) → Bosch BMM150（很高置信）
  • 高 g：±200g / 5 mg/√Hz / 1600Hz → ADI ADXL375（中高置信）
  • 温度传感器为独立器件（量程 −104~150°C，三颗 MEMS 都达不到）

CAD 布局：磁力计在板角、远离 USB/电源；高 g 靠近板边与安装孔； 主 IMU 避开板边应力区。三种传感器各自独立标定（15 参数）。

ATOM-IMU：双 6 轴 + 单一加热区

  • BMI088 + BMI270（固件字符串中仅见这两个传感器驱动）
  • 没有磁力计：航向靠陀螺积分，零漂只能靠零偏稳定性
  • 没有高 g：定位是精密姿态，不是冲击记录
  • 板上有黄色功率电阻（加热）与 220µF/16V 电解电容（加热脉冲储能）
  • 两颗 IMU 共享一个热区，命令层同步目标温度

这解释了它的工程取舍：既然没有磁来兜底航向，就必须把温度与零偏做到极致—— 恒温 45°C + 0.13°C 稳定判据 + 温态标定。

实板一锤定音：读 WHO_AM_I 即可确认——BMI088 加速度计 0x1E、陀螺 0x0F； BMM150 0x50；ADXL375 DEVID 0xE5。

7混合融合：学术与工业界的真实做法

“Madgwick 先出四元数，再喂给 EKF”确实有论文，但工业界主流不这么做。 原因不是实现难度，而是信息重复、延迟叠加，而且没有新增信息。

学术串联方案确实存在

Kong 等，Attitude solving method based on fusion of Madgwick and EFK， YAC 2023，DOI 10.1109/YAC59482.2023.10401414。 做法是 Madgwick 先融合 IMU 得到初始四元数，再把四元数作为 EKF 的观测量； EKF 的状态方程仍由角速度和加速度建立。论文报告对加计突变/非重力加速度的抑制更好。

问题：EKF 的预测又用了 Madgwick 已经用过的同一组陀螺和加计， 两个估计误差相关，Kalman 的独立性假设被破坏；论文没有做协方差一致性分析。 这是“存在性证明”，不是产品级最佳实践。

理论两者本来就是同一家族

Jensen 2011，Generalized Nonlinear Complementary Attitude Filter （arXiv:1110.0274）证明： 无零偏、常增益的乘性 EKF 是广义非线性互补滤波器的特例。

Madgwick/Mahony 与 EKF 不是两个独立传感器，而是同一观测器家族的不同参数化。 串联不会引入新的独立观测，只是把同一份信息换一种方式再算一遍。

其他参考：Ludwig & Burnham 2018（DOI） 在四旋翼飞行数据上对比 EKF/Madgwick/Mahony；Teague 2016（arXiv:1602.07733） 对比互补滤波/EKF/UKF；Yamagishi & Jing 2026（arXiv:2607.05451） 用自适应互补滤波在更低算力下取得低 RMSE。

共同模式：IMU 负责预测，辅助传感器负责修正，所有观测进同一个估计器； 传感器延迟用时间戳/缓冲补偿，而不是再串一个滤波器。

来源： PX4 EKF2 文档、 ArduPilot AP_NavEKF3_core.h、 VectorNav VN-100、 x-io x-IMU3。

为什么串联不划算

  • 信息重复：Madgwick 已经用了 gyro + accel + mag；EKF 再用同一组数据， 两个估计误差相关，R 无法正确建模，滤波器会过度自信。
  • 没有新增信息：姿态可观测性来自重力（2 自由度）+ 磁航向（1 自由度）。 两个滤波器用同一份观测，稳态精度下限相同；串联最多是把 Madgwick 的输出平滑一遍， 不会降低噪声底。
  • 延迟叠加：Madgwick 的跟踪延迟约一个采样周期，EKF 再加一个； 串联后比任何单滤波器都慢。
  • 理论同源：常增益、无零偏的乘性 EKF 就是互补滤波的特例（Jensen 2011）—— “融合”并没有引入第二个独立传感器。

8按端侧算力分档的取舍

除姿态解算外还要跑飞控，所以关键不是“能不能跑”，而是“留多少余量”。以下按 400 Hz 姿态更新估算。

80 MHz 档M0+ / M3（无 FPU）
  • 选型：Madgwick（9 轴或 6 轴），400 Hz；定点化可选。
  • 预算：AHRS ≈3%，飞控 1–2 kHz ≈10–20%，其余留给通信/日志。
  • 不要做：任何 6×6 以上矩阵 EKF（软浮点会吃掉 50%+）。
  • 补偿：用初始化窗口 + 缓慢零偏 EMA；磁干扰用计数门控。

结论：Madgwick 是唯一现实选择；把省下的算力留给飞控。

170 MHz 档STM32G4 / H5（M4F / M33）
  • 选型：ES-EKF 6 状态（δθ+δb），400 Hz，≈5%。
  • 预算：飞控 2–4 kHz ≈5–10%；温控 10 Hz 可忽略。
  • 关键：必须用 float；double 在 M4F 是软件实现（ekf7 当前默认 double，移植时务必改）。
  • 可选：ZUPT（静止场景）、P7 温补（无烤箱时）。

结论：这是“姿态质量/算力”最甜的一档，6 状态 ES-EKF 足够。

280–300 MHz 档STM32H7A3 / H7B3（M7）
  • 选型：ES-EKF 9 状态（δθ+δv+δb），400–1000 Hz。
  • 预算：AHRS ≈1–3%；飞控 4–8 kHz 仍有充足余量。
  • 可选：ZUPT + 磁航向联合、P7 温补、在线安装矩阵。
  • 注意：M7 有双精度 FPU，double 可用但仍建议 float 以省周期。

结论：可以同时要“精度 + 速度 + 协方差”，为飞控留出大半算力。

480–600 MHz 档H743 / H723 / H7R（M7）
  • 选型：ES-EKF 12 状态（含 δk 温漂斜率），1 kHz AHRS。
  • 预算：AHRS ≈1–2%；飞控 8 kHz + 通信/日志仍轻松。
  • 增值：原始数据高速记录、双 IMU 冗余、在线健康监测。
  • 提醒：更高的主频不会自动带来更高精度——标定与温控仍是上限。

结论：算力不再是约束，把预算花在标定、温控与验证上。

一个容易踩的坑：自研 ekf7 的 C 移植默认 typedef double ekf7_real。 在 M4F（G4/H5）上 double 是软件浮点，实测/估算成本约为 float 的 3–4 倍， 且代码尺寸从 13.3 KB 涨到 19 KB。若目标 ≤170 MHz，先切 float 并重跑差分验证。

  • 传感器/MCU：LSM6DSV / LSM6DSO / ICM-42688；nRF52 / STM32L4 / RP2040。
  • 延迟：有线 <5 ms、BLE <10 ms；报告率 100–1000 Hz，按游戏类型选。
  • 工程：出厂零偏/灵敏度校准；静止零偏跟踪；低功耗待机；避免在传感器端做重滤波。

选型原则（按优先级）

  1. 先定观测量，再定算法：要绝对航向就必须有可信磁/视觉/双天线 GNSS；没有就接受相对航向，用回中/轮速/视觉补。
  2. 再定内环速率：速率环 >1 kHz 时，姿态解算必须与内环解耦；内环直接用陀螺。
  3. 再定 MCU：M0+ 只跑 Madgwick；M4F 起步跑 ES-EKF6；M7 跑 ES-EKF9/12 + 1 kHz。
  4. 最后定 IMU：姿态精度看陀螺噪声密度/零偏稳定性，不看量程；动态大选高 ODR/抗振，电池设备选低功耗。
  5. 温度是隐藏变量：有功耗预算上恒温（ATOM）；没有就用 P7 温补 + 出厂/产线标定。

10与飞控共存的调度建议

推荐速率与优先级

任务速率优先级说明
飞控内环（PID）1–8 kHz最高硬实时，不可被姿态解算阻塞
姿态解算400 Hz–1 kHz高与 IMU 采样同步；可降频到 400 Hz
导航/速度（ZUPT）100–400 Hz中可与姿态同拍或抽拍
温度控制10 Hz低热时间常数大，10 Hz 足够
标定/参数维护模式最低飞行中禁止触发

工程要点

  • 中断/DMA 收数据：SPI 传感器用 DMA 搬运，解算在主循环或低优先级线程。
  • 时间戳 dt：用硬件时间戳而不是固定 1/fs（x-IMU3 的做法），抗丢包与时钟偏差。
  • 分级降频：CPU 紧张时先降 EKF 到 200 Hz，再降磁观测到 50 Hz；不要降飞控。
  • 浮点：M4F/M33 一律 float；M7 可 double 但无必要。避免在中断里做矩阵运算。
  • 内存：ES-EKF6 的 P 仅 144 B（float）；ekf7 double 的 P 为 392 B，另加状态与栈。

11落地路线（建议顺序）

  1. 先做公共底座：ATOM 式 12 参数标定 + 温度稳定门控（0.13°C）+ x-IMU3 式初始化窗口。这三件事对三档滤波器都有效，且运行成本近零。
  2. Tier 1 原型：把 fusion-design/bench/esekf6.c 扩成完整实现（补 ZUPT/自适应 R/复位），在 G4/H5 上跑 400 Hz；用自研工程的差分测试方法验证。
  3. 并入鲁棒机制：观测抑制计数器（−9/恢复触发）、超量程恢复、时间戳 dt——直接照搬 x-IMU3 的行为。
  4. 温补：有加热硬件走 ATOM 恒温；没有则上 P7（b(T)=b0+kΔT），两者可叠加。
  5. 基准回归：同一份真实数据跑三档实现，比较姿态误差/零漂/CPU；合成数据只用于机制验证，不替代真机。
